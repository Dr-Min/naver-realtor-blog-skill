# Browser and report contract

## Browser surface

Use the Codex in-app Browser and its persistent browser profile. Check whether Naver is already authenticated.

- If authenticated, continue without asking for login.
- If logged out, expired, challenged, or switching accounts, navigate to Naver and ask the user to complete login directly in the browser.
- Do not ask for credentials in chat.
- Do not read, export, copy, serialize, or log cookies or session tokens.
- Never attempt configuration-file login automation.

Pin a privacy-safe target-blog fingerprint after the first successful draft. If the active target does not match, stop before writing.

## Naver editor

Assign one sequential owner.

1. Read the locked deterministic payload.
2. Open the correct Naver editor.
3. Verify target blog and draft baseline without logging raw account identity.
4. Enter the exact title and ordered blocks.
5. Upload each authorized photo at its anchor.
6. Select each image if needed and visibly enter its caption.
7. Verify title, disclosure, conditions, headings, ordered text, image count/order, captions, and tags.
8. Click only “임시저장”.
9. Verify a draft-count change or editor confirmation.
10. Record a privacy-safe result.

Never click publish, schedule, audience/publication settings, or paid promotion. If structure cannot be verified, do not save a malformed draft.

## Save result

Record:

- success, blocked, or failed;
- timestamp;
- target match;
- draft evidence before/after;
- payload hash;
- verified title, image count/order, and captions;
- retried actions;
- publication false;
- safe user recovery instruction.

## Human HTML report

Create exactly one self-contained report. Make it readable on desktop and mobile.

Include:

- executive status and draft-save result;
- normalized human input and excluded/missing fields;
- inferred audience, evidence, counterarguments, alternatives, and confidence;
- 3A/3B/3C methods, settings, URLs, screenshots, raw-file links/hashes, and limitations;
- candidate comparison and selected/rejected keyword reasons;
- reasons-for-reasons and what would overturn the decision;
- content plan, photo mapping, QA findings, remediation, and payload hash;
- model/agent routing;
- chronological event log;
- cache decision;
- integrity receipt and unresolved limitations.

Show DataLab filters, graph, and legend at readable sizes. Show long Blog-search evidence uncropped or in a labeled scrollable viewer. Never stretch images; preserve aspect ratio.

A failed enhanced-reader or rendering verifier is a reportable limitation. Do not relabel it as passed. If a semantic fallback is used, record the failed receipt, fallback method, structural equality result, and visual check.

## Report safety

Do not embed raw account IDs, cookies, credentials, hidden browser state, internal chain-of-thought, or private addresses beyond the user's public boundary. Present concise reasons, evidence, counterarguments, and reproducible receipts.
